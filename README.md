# technical-writing-ko

AI가 쓴 한글 문장을 **읽을 수 있는 문서**로 만듭니다.

## 설치

### Claude Code

```
/plugin marketplace add joshyeom/technical-writing-ko
/plugin install technical-writing-ko
```

설치한 뒤 클로드 코드 출력 형식을 변경할 수 있습니다.

```
/output-style
```

목록에서 `Korean Plain`을 고르면 이번 세션부터 적용됩니다.

되돌릴 때는 `/output-style`에서 `Default`를 고릅니다.

### 그 외 에이전트

Codex, Cursor, OpenCode, Gemini CLI 등 77개 코딩 에이전트를 지원합니다.
출력 문체는 Claude Code 전용이라 스킬만 들어갑니다.

```bash
npx skills add joshyeom/technical-writing-ko
```

에이전트를 지정하려면 `-a`를 씁니다.

```bash
npx skills add joshyeom/technical-writing-ko -a codex
npx skills add joshyeom/technical-writing-ko -a cursor
npx skills add joshyeom/technical-writing-ko -a opencode
npx skills add joshyeom/technical-writing-ko -a gemini-cli
```

여러 개를 한 번에 지정할 수도 있습니다. 

```bash
npx skills add joshyeom/technical-writing-ko -g -a codex -a cursor
```

Claude Code에 스킬만 넣고 싶을 때도 같은 명령을 씁니다.

```bash
npx skills add joshyeom/technical-writing-ko -g -a claude-code
```

### 사용법

문서를 쓰거나 다듬을 때 자연어로 부르면 됩니다.

```
보고서 써줘
이 문서 AI 티 없애줘
번역투 고쳐줘
음슴체로 바꿔줘
대시 좀 빼줘
```

## 목적

한글 윤문 도구는 이미 여럿 있습니다. 이 도구는 목표가 다릅니다.
문장을 다듬는 것이 아니라 **문서를 만드는 것**이 목적입니다.

**1. 모델이 배운 한글 작문 습관에서 벗어납니다.**
Claude와 Codex는 영어권 글쓰기 교육을 학습했습니다. `Use strong verbs`,
`Show, don't tell` 같은 규범입니다. 그 규범이 한국어 기술 문서에도
그대로 적용되면서 어색한 문장이 나옵니다. 단어는 한국어인데 고르는 기준이
영어입니다.

**2. 과한 은유를 걷어냅니다.**
`DB를 때린다`, `병목이 박힌다`, `큐 깊이를 갉아먹는다`. 조회인지 쓰기인지 부하 테스트인지
읽는 사람마다 다르게 해석합니다.

**3. 줄표를 없앱니다.**
`—`와 `–`는 영어 문장부호 미학입니다. 한국어는 전통적으로 마침표로 끊거나
괄호를 씁니다. AI가 쓴 한글에서 가장 눈에 띄는 흔적이기도 합니다.

**4. 프롬프트만이 아니라 결과물까지 정제합니다.**
출력 문체(output style)를 같이 넣었습니다. 채팅 답변에도 같은 규칙이 걸립니다.
문서를 만들 때만 깨끗하고 대화는 그대로인 상태를 피하려는 것입니다.

이 문단에서는 두 윤문 도구가 **한 글자도 바꾸지 않았습니다.** 고칠 근거가 되는
패턴이 목록에 없기 때문입니다. 실행 로그에도 그렇게 남았습니다.

> 은유 술어 군집. 한 문서에 8개 몰려 있어 가장 AI스러운 지점이지만
> 40패턴 중 대응 항목 없음.

그래서 이 도구는 목록 대신 판별법 한 줄을 씁니다.

> 술어를 손으로 하는 동작이나 물리 현상으로 그릴 수 있는데,
> 글의 주제는 물리적인 게 아니라면 은유다.

목록에 없는 동사도 이 판별법에 걸립니다. 위 표의 `삼키다`, `얹히다`,
`갉아먹다`, `맞물리다`, `새어나가다`는 어느 패턴 목록에도 없는 말입니다.

## 구조

세 층으로 나눴습니다. 기계가 셀 수 있는 것과 판단이 필요한 것을 섞지 않습니다.

**Layer 1. 기계 스캔.** 줄표, 이중피동, 곡선따옴표, 메타 담화, 번역투 조사를
`grep`으로 전수 처리합니다. 최종본을 내기 직전에 같은 스크립트를 다시 돌려
0건인지 확인합니다.

**Layer 2. 원칙 리뷰.** 패턴 ID를 나열하는 대신 원칙 여섯 개와 대조 예시를 둡니다.
목록에 없는 표현이라도 원칙에 어긋나면 잡고, 원칙에 안 걸리는 멀쩡한 문장은
고치지 않습니다. 문장 단위 다섯 개에 더해, 배경만 읊는 상투 서두와
요약에 당위를 붙이는 결말, 문단마다 붙는 접속부사 같은 구조 상투구를
지우는 원칙이 하나 있습니다. 문단을 재배치하지는 않고 지우기만 합니다.

**추측 금지.** 은유를 걷어내면 실제로 무슨 동작인지 빈자리가 생깁니다.
원문에 없으면 지어내지 않고 중립 동사로만 낮춘 뒤 `미해결`로 보고합니다.

## 문체

기본은 '합쇼체'입니다. 아래 순서로 정하고, 위에서 걸리면 아래는 보지 않습니다.

1. 사용자가 말한 것 (`해요체로`, `음슴체로`)
2. 기존 문서를 손보는 경우, 원문의 어미
3. 문서 유형 (보고서는 합쇼체, 가이드는 해요체, 메모는 음슴체, 분석은 한다체)
4. 판단이 안 서면 합쇼체

본문만 정한 문체를 쓰고, 표와 불릿과 레이블은 개조식으로 분리합니다.
표 안에 `수정 사항이 없습니다`가 아니라 `수정 사항 없음`이라고 씁니다.

## 출력 문체 (Claude Code 전용)

채팅 답변에도 같은 규칙을 걸 수 있습니다. 문자와 어법만 고치고 답변 길이나
불릿 서식은 건드리지 않습니다. 켜는 방법은 위 설치 절에 있습니다.

같은 질문에 세 번 물어본 결과입니다.

|---|---|---|
| 기본 | 10 | 2 |
| Korean Plain | **0** | **0** |

## 쓰지 않아야 할 곳

문장을 평범하게 만들기 때문에, 은유적인 표현이 있는 칼럼, 에세이, 마케팅 글에는 쓰지 마세요.
정확성이 우선인 기술 문서 및 리포트 전용입니다.
